# Product

## Register

product

## Users

Developers and platform teams operating RAG applications. They use the Console to create isolated projects, inspect queries and traces, run reproducible evaluations, and promote verified releases.

## Product Purpose

ORAG provides a dependable control surface for the Go-native RAG service framework. Success means users can move from ingestion and retrieval debugging to evaluation and release with clear system state, auditable evidence, and minimal operational friction.

## Brand Personality

Technical, restrained, and trustworthy. The interface should feel precise and calm while keeping complex runtime information legible.

## Anti-references

Avoid decorative motion, opaque system state, invented operational claims, dashboard ornament, and visual changes that make established workflows harder to scan.

## Design Principles

- Show verified system state and provenance instead of inferred success.
- Keep common developer workflows fast, predictable, and keyboard accessible.
- Prefer small, measurable improvements over broad visual or architectural rewrites.
- Preserve operational safety and explicit failure recovery.
- Let dense technical information remain readable without hiding important detail.

## Accessibility & Inclusion

Preserve semantic controls, visible keyboard focus, reduced-motion support, readable contrast, and responsive layouts down to the existing 320 px minimum viewport.
